# 全景轮廓编辑与多帧点云候选（0.14.0）

0.14.1 新增“圈选范围”。新对象默认完整物体，需要将正面和侧面一起圈入外轮廓；旧数据按单面解释。下面 0.14.0 的每帧近表面/PCA 说明仅对应单面路径；完整体积改为所有轮廓内、至少一帧可见，再用水平最小面积方向拟合。接口与操作以 [墙体厚度修正](WALL_VOLUME_0.14.1.md) 为准。

## 操作流程

1. 在“标注 → 点云 + 全景”选择类别和“多帧目标框”。默认方式为“多边形轮廓”。沿目标边缘依次点击，斜面可点四角，不规则物体可增加顶点；按 Enter、双击最后位置或点击“完成轮廓”闭合。两点矩形保留在方式下拉框中。
2. 保持选中同一对象，切到相邻帧，再圈同一目标。每帧保存独立轮廓，共享对象 ID。至少两帧有已导入/校正的位姿后点击“多帧定位”。
3. 检查点云里的候选框，必要时用移动、尺寸、旋转手柄修正，最后“确认 3D 结果”。支持点数表示算法用于拟合的点数，框内点数可能更大；两者都不是准确率。
4. 点击“保存更改”保存已完成的标注；“导出结果”保留完整顶点、逐帧位姿和候选来源。草稿和撤销历史仅在当前页面内保留。

“全景多边形”使用同一套绘制、拖动和撤销机制，生成当前帧的 2D 标注。它不会自动变成多帧观测；需要跨帧定位时使用“多帧目标框”。浏览工具可通过点击轮廓内部重新选中对象，也可以从右侧对象列表选择。编辑手柄仅在标注页出现，配准页只显示已有轮廓用于投影核验。

## 修改与快捷键

| 操作 | Windows | macOS |
| --- | --- | --- |
| 完成绘制 | Enter / 完成轮廓 | Return / 完成轮廓 |
| 撤销 | Ctrl+Z / 撤销 | Cmd+Z / 撤销 |
| 重做 | Ctrl+Shift+Z，或 Ctrl+Y | Cmd+Shift+Z，或 Cmd+Y |
| 移动顶点 | 拖动编号圆点 | 拖动编号圆点 |
| 删除顶点 | 选中顶点后 Backspace / Delete / 删除顶点 | 选中顶点后 Delete / 删除顶点 |
| 补点 | 选中顶点，点“在其后加点”，再拖动新点 | 相同 |
| 取消本次绘制 | Esc / 取消绘制，可撤销 | 相同 |

绘制中未选中顶点时，Backspace 删除最后一个点。已闭合轮廓至少保留三个顶点，最多 256 点，拒绝重合边、自交和跨度过大的轮廓。拖动期间只预览，松开后形成一次可撤销操作；它不会旋转全景或同步点云视角。“重绘当前轮廓”清除本帧轮廓后重新圈选，“删除当前轮廓”保留其他帧及对象身份；这两个操作也可撤销。

历史最多保留 60 次操作，可恢复对象创建、轮廓完成、顶点编辑及其关联的候选状态；撤销完成会回到未闭合的草稿。切帧时未完成草稿会取消，可撤销回原帧继续。切任务、刷新页面或更改配准会清空历史；更改配准时清空是为了防止撤销恢复基于旧位姿的核验状态。点云涂抹仍使用自己的“撤销涂抹”，外参/同名点不在轮廓历史范围内。

修改任何已有多帧轮廓会清除该对象由定位产生的 3D 框和核验标记，必须重新定位并确认。撤销轮廓修改可以恢复修改前与轮廓匹配的候选。配准改变则将旧候选标记过期，不能直接确认。绘制尚未完成时也不能定位或确认旧候选。

## 几何与接口

`TargetObservation` 新增可选 `vertices: [u,v][]`，范围 `[0,1]`，以等距柱状全景原图为基准，与用户当前观察角度、缩放无关。保留 `frameId`、`bounds` 和 `center`，导出仍为 schemaVersion `0.2`。例子：

```json
{
  "frameId": "F001",
  "vertices": [[0.46,0.42],[0.53,0.44],[0.55,0.60],[0.47,0.57]],
  "bounds": [0.46,0.42,0.55,0.60],
  "center": [0.50,0.51]
}
```

示例 `center` 为说明性数值；实际值由球面方向均值计算，跨 0/1 接缝时按球面处理。顶点相邻边对应球面短弧（在当前透视视图里显示直边），并非对展开图直接画经纬度直线。超过单个前向半球、接近反向的巨大轮廓需要拆分。

旧记录缺少 `vertices` 时按 `bounds` 恢复四角，仅编辑的当前帧升级，其他帧保持原值。旧的全矩形对象仍保留原中心射线定位路径；一旦包含新轮廓观测，定位会对所有观测使用实际顶点或兼容四角形成的球面掩膜，不能将旧帧外接矩形当作精细轮廓。

新路径在每帧轮廓方向的切平面中做包含判断，处理透视倾斜、凹多边形和全景接缝。将显示点云投影到所有帧，取轮廓交集，利用每帧 64×64 深度格及 3×3 邻域最近深度加 0.4 m 的容差抑制背景。对保留点用 0.35 m 体素的 26 邻域取最大连通分量，至少需要 12 个支持点。随后在水平面做 PCA，按各轴 1%–99% 分位范围加 0.08 m 余量，最小尺寸 0.12 m，生成有 yaw 的候选框。

仍要求至少两帧独立位姿、最大基线 ≥0.1 m、中心方向最大视差 ≥1.5°。新路径的中心射线偏差只作诊断，不能当作同名物理点重投影误差；框中心到最近点云的距离也仅作诊断（空心/大物体的中心可以不在表面）。旧射线路径保留中位偏差 ≤2 m、正深度、中心到点云 ≤2 m 的检查。

`triangulation.method: "silhouette"` 和 `supportPointCount` 标明新候选来源。轮廓顶点保留在导出 JSON 中，供未来分割/多视角模型使用。现有 HTTP 预标注、千问/DeepSeek、蒸馏训练接口不变；本次几何候选不会直接生成逐点语义标签，也不会绕过人工审核写入训练数据。

## 代码入口与验证

- `src/PanoramaEditor.tsx`：与球面相机一致的屏幕顶点手柄，指针捕获，松开提交。
- `src/ContourTools.tsx`：上下文操作栏，不新增主导航或配准参数。
- `src/panoramaContours.ts`：轮廓校验、接缝、兼容读取、观测更新、可见点交集及候选拟合。
- `src/annotationHistory.ts`、`src/App.tsx`：跨帧快照、草稿与历史、派生结果失效、保存导出。
- `src/registrationMath.ts`：按观测类型选择新轮廓路径或旧中心射线路径。
- `scripts/test_panorama_contours.mjs`：凹轮廓、自交、重复点、跨接缝、旧矩形、斜墙与背景/地面干扰、跨帧修改、撤销/重做和历史边界。

运行 `npm run test:contours`、`npm run test:registration`、`npm run test:view-sync`、`npm run test:workflow` 与 `npm run build`。真实图书馆数据的 Windows Chrome 操作验证使用独立 localhost 存储，不覆盖用户 127.0.0.1 上原有四帧标注。两帧四角轮廓产生 898 个支持点的墙面候选，拖动不改变相机姿态；增删点、撤销重做、修改后候选失效、保存刷新均通过。导出和截图仅保留本机 `release/`。

这不是通用精度验收。遮挡、透明面、原始点云稀疏、位姿偏差和轮廓误圈可能使交集不足或选错连通区域，固定的深度/连通阈值也可能漏掉目标。仅圈可见面时，厚度反映可见支持点的范围，不能推断被遮挡背面的真实厚度。当前 Cuboid 仍只有水平 yaw，不支持完整 roll/pitch；需要人工补尺寸，或后续增加完整姿态框。macOS 使用相同代码及打包流程，实体 Mac 的图形交互仍需验收。
