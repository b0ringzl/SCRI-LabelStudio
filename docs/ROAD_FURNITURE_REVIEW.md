# 道路设施图片复核任务

## 本批次数据

以用户提供的 `label/data` 目录为准。当前待复核集是 `data_for_annotation`：`images/` 与 `labels/` 各 900 个同名文件，`class.txt` 规定类别顺序。现有 5,442 个 YOLO 框，其中 113 张图的标签文件为空。空标签是待人工检查的图片，不等于已经确认没有目标。

`road_forniture_add_v2`（660 张、LabelMe 风格 JSON）和 `road_furniture_add_v3_200`（202 张、YOLO TXT）可作为已标案例与裁剪图参考。前者的 `class.txt` 列出 6 类，但其 JSON 中也有 `pole` 框；因此不要把这个类表当作本批次的 7 类映射。三个目录及 PPTX 原文件不进入 GitHub 或交付 ZIP。

本批次只有普通 JPG 影像和 2D 框，没有点云或同步全景数据。项目原有的点云/全景联合工作台仍是独立入口；不能从这批文件推断 3D 配准关系。

## 类别与编号

YOLO 第一列必须使用以下固定编号，顺序与 `data_for_annotation/class.txt` 一致。

| 编号 | ID | 规范含义 |
| --- | --- | --- |
| 0 | `sign` | 不属于以下专类的大多数交通标志牌 |
| 1 | `sign_s` | 黑白街道名称牌 |
| 2 | `fence` | 隔绝行人的铁栏；道路中间网状铁栏 |
| 3 | `sign_p` | 通常含人形符号的交通指示牌 |
| 4 | `fence_v` | 隔绝车辆的石质、连续铁质高速围栏，或临时红白围栏 |
| 5 | `sign_d` | 蓝色、绿色的大型车辆引导牌 |
| 6 | `pole` | 上述交通标志牌的主杆 |

## PPTX 中的复核规则

以 `road_fortunture_annotation_v3.pptx` 为最新说明，前两版用于对照。

- 连续的 `fence` / `fence_v` 尽量使用一个框；明显中断，或被人、车等物体遮挡时再分开。广告帆布遮挡围栏的案例中，说明要求把遮挡部分单独标成 `fence`。
- 四种标志牌的背面也要标。很小的目标可以不标；近处或大型的不同牌子应尽量分开。远处、小型且边界不清时可以合成一个框；侧面窄到无法识别时可以不标。
- `pole` 只画交通标志牌的主杆。部分 `sign_s` 可有两根主杆。公交站牌、路灯、交通灯等其他杆不标；若标志牌直接挂在较粗的路灯柱上，该柱不标。
- AI 预测只是待复核初值。逐张移除重复框、纠正类别及边界、补充遗漏，检查完才点击“确认并下一张”。

## 工作台操作

1. 本机源码目录若有忽略提交的 `.atlas-local-data.json`，启动 `node scripts/serve.mjs` 后会自动读取配置中的 `reviewDataDir`。服务只监听 `127.0.0.1`，原始数据保持只读。
2. Windows/macOS 交付 ZIP 默认不带真实数据。解压并启动后，点击“选择数据文件夹”，选中整个 `data_for_annotation`；若浏览器不支持目录选择，也可分别多选图片和 TXT 标签。
3. 在图像空白处拖出新框；拖现有框移动，拖选中框四角调整大小。点击右侧类别或按 1–7 改类，Delete 删除，Ctrl+Z（macOS 为 Command+Z）撤销。放大后可滚动查看小目标。
4. “疑似重复”按框间 IoU ≥ 0.85 提示，不自动删除；跨类别重叠也会提示，需人工判断。
5. 每次编辑与确认会写入当前浏览器 `localStorage`。目录选择导入的图片文件本身不会持久保存，刷新后需重选文件夹；同名任务的编辑结果会恢复。定期点击“导出 YOLO ZIP”备份。另一位同事先载入同一图片目录，再点“导入进度 ZIP”继续复核；导入会覆盖当前浏览器中的该批次进度。

导出 ZIP 含 900 个 `labels/*.txt`、`class.txt` 和 `review_manifest.json`，不含 JPG。`review_manifest.json` 记录每张图是否已确认及框来源；未确认的标签也会导出，不能把“已导出”视为“全部复核完成”。原始 `labels/` 不会被覆盖。

## 代码与后续接口

- `src/ImageReview.tsx`：任务队列、框编辑、审核状态、YOLO 导出。
- `src/reviewData.ts`：固定类别、YOLO 读写、疑似重复计算。
- `scripts/serve.mjs`：可选的本地目录只读接口 `/api/review-manifest` 和 `/api/review-image/{name}`。
- [模型接口说明](MODEL_API.md)：当前读取现有 YOLO 预标注，尚未调用推理模型。模型同事需保证输出类别编号与归一化框格式一致。
