# 0.14.0：可编辑全景轮廓与多帧点云筛选

## 解决的问题

全景里的斜置宣传墙、透视立面和不规则物体无法用两个对角准确描述，矩形会混入地面或漏掉目标。原先多帧定位只使用框中心射线，轮廓没有参与点云候选拟合；点击后的顶点也不能修改。

## 功能变化

1. 多帧目标框默认逐点轮廓，可四角或任意多边形，保留两点矩形快捷方式。各帧独立保存归一化球面顶点，同一对象跨帧关联。
2. 完成前后均可拖动顶点。选中编号点后可删除、在后方边上补点，或重绘/删除当前帧轮廓。新增 Enter 完成、Esc 取消、Backspace 删除、Windows Ctrl / macOS Cmd 撤销重做，60 步页面内历史。一次轮廓拖动只占一次撤销。
3. 新轮廓进入多帧几何筛选：精确包含判断、跨帧交集、近表面深度筛选、连通区域及水平旋转框拟合，新增支持点数与来源字段。仅有旧矩形的对象继续使用旧中心射线计算，编辑后可逐帧升级。
4. 修改已定位轮廓后自动清除旧候选及核验标记；撤销能还原匹配的候选。绘制中、计算中、外参变动导致候选过期时禁止确认旧结果。
5. 工具下增加一行上下文编辑栏；浏览模式可点轮廓内部选择。顶点拖动捕获指针，保持同步观察视角；清理重建标注图元时释放 GPU 资源。编辑手柄只在标注页开放，配准页保留投影核验，增加回归验证此边界。

## 开发接口与文档

新增可选 `TargetObservation.vertices`，保留 bounds/center/schemaVersion 0.2 和旧数据。新增 `triangulation.method="silhouette"` / `supportPointCount`。代码分离为 PanoramaEditor、ContourTools、panoramaContours、annotationHistory；完整交互、算法阈值、数据格式、兼容行为和同事开发入口见 [轮廓编辑说明](PANORAMA_CONTOUR_EDITING.md)。README、UI 设计、架构、模型 API 与双平台说明同步更新。

## 验证与交付

新增几何/历史回归，纳入 GitHub CI；已有配准、同步视角和四步流程回归通过。Windows Chrome 实测图书馆两帧宣传墙：898 个支持点生成候选；逐点撤销、整次拖动撤销、插入与删除、派生框失效及保存重载通过。用户原有四帧标注单独备份，测试使用独立本地工作区。

提供相同功能的 Windows/macOS 常规包与本地四场景试用包。真实数据、用户备份、UI 导出、截图和 ZIP 不提交仓库。macOS 的实体 GPU 交互待验收。候选只有 yaw；可见面拟合不能推断完整物体厚度，也不是配准精度或语义分割准确率证明。
