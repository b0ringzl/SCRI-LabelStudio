# DA² 配对场景测试指南（Windows / macOS）

适用应用 0.16.0。测试包使用用户已有的真实点云、原始全景及逐帧位姿；共四场景、32 帧。没有用 DA² 预测深度反生成“测试点云”，也没有把虚拟图片混进实拍全景。数据与结果仅留在本地，GitHub 只存生成工具、格式与说明。

## 1. 文件与测试顺序

| 场景 | 点数 | 全景数 | 建议先测 | 测试重点 |
| --- | ---: | ---: | --- | --- |
| 六层 floor6 | 1,066,346 | 7 | 76.jpg，再试 72.jpg | 深度生成、候选预览、换帧、人工确认 |
| 校园 campus | 1,447,166 | 7 | 100.jpg | 室外树木与远景，拒绝候选时保留原位姿 |
| 图书馆 library | 1,667,193 | 7 | 4324.jpg | 建筑、遮挡和错误候选的拦截 |
| 尖沙咀 jianshazui | 6,215,955 | 11 | frame_001298.jpg | INS 粗初值、大场景、局部 RGB 与全局概览 |

前三组显示点云保留原地图范围，经空间体素降采样；不是全部原始点。尖沙咀包含全部 12 个 DS 分块的降采样全局概览及 450 万局部 RGB 细节点；全局灰度是强度显示。没有进一步裁剪或二次压缩这次打包的点云、全景。天空、遮挡和源扫描空缺处仍可能没有点。

套件结构：

```text
SCRI-DepthTests-<Windows或macOS>-v0.16.0/
  Start-Tests-<平台启动器>
  Setup-Depth-<平台启动器>
  scripts/、dist/、docs/             应用与安装脚本
  TEST_GUIDE.md                     本指南
  test-plan.json                   五个参考测试用例
  test-suite.json                  点数、图像尺寸、来源说明、逐文件 SHA-256
  scene-data/
    scene-catalog.json             四场景目录，默认六层
    floor6/、campus/、library/、jianshazui-v2/
      scene-cloud.pcd
      registration.json           逐帧 cameraToCloud
      source-metadata.json        源采样与粗位姿说明
      panoramas/*.jpg             原始全景，与位姿逐帧配对
```

每个场景目录本身也是完整的独立场景。可复制任意一个目录，用已有应用的 `--scene-dir` 指向它，单独测试；不必拆分大点云或手动配对图片。

## 2. 在当前电脑直接试用

如果已打开附带的本机测试链接，可直接进入“数据”选场景，随后进入“配准”。当前项目已有独立 DA² 环境与权重，无须再次安装。数据源文件与 TREE 项目不作修改。

首次试用建议不要应用候选，先在六层 76.jpg 比较原位姿与候选，随后检查其他帧。已有浏览器标注及已保存的位姿可能继续加载：这些数据副本沿用原场景 ID，不自动清空历史。需要可重复的全新测试时，使用浏览器隐私窗口；或在“粗配准 → 导入位姿”中导入该场景的原始 `registration.json` 恢复本次文件初值。先导出需要保留的工作结果。

## 3. 解压到另一台电脑

### Windows

1. 将 Windows ZIP **完整解压**到可写目录，勿在压缩包预览窗口内运行。
2. 安装 Node.js 20+。新电脑还需按 `docs/DEPTH_REGISTRATION.md` 安装 Python / Git，并运行 `Setup-Depth-Windows.bat` 一次。它会下载官方 DA² 权重到本包目录，创建独立 Python 环境。
3. 双击 `Start-Tests-Windows.bat`。浏览器自动打开后默认使用六层场景。
4. 关闭该启动窗口或在其中按 Ctrl+C 停止本次服务。不要结束其他项目的进程。

### macOS

1. 完整解压 macOS ZIP；安装 Node.js 20+、Python / Git。DA² 当前安装脚本面向 **Apple Silicon**。
2. 在解压目录打开终端，首次执行 `sh ./Setup-Depth-macOS.command`，完成独立环境和官方权重安装。
3. 执行 `sh ./Start-Tests-macOS.command`；若系统允许，也可双击该启动器。
4. 在对应终端按 Ctrl+C 停止服务。macOS 包文件结构、启动参数和 CPU 几何验证有检查；DA² 的 MPS 推理效果与交互性能仍需实体 Mac 验收。

两个包带相同场景数据与应用构建，不包含 Python 运行时或约 1.38 GB 模型权重。已经在别处安装的环境不会自动复制进新解压包；要免重装，可直接使用当前项目的本机测试链接。启动器从 44010 端口起选择空闲端口，仅监听 127.0.0.1，不占用或关闭旧项目服务；以启动窗口打印的实际地址为准。

## 4. 完整操作流程

1. **加载配对数据**：“数据”选择“六层”，进入“配准 → 粗配准”，确认帧为 `76.jpg`。初始矩阵已经随场景加载，不需要再次选择散落的文件。
2. **先查粗配准与同步**：在分开视图转动全景，确认点云朝向同步；切到前后帧，确认点云观察位置随帧位姿变化。再看点云投影叠加，判断墙、地面、立柱的对应关系。
3. **运行 DA²**：在自动精配准设置选择 DA² 深度辅助方法，点击“自动精配准”。本次输入是当前全景、附近 XYZ 点和当前粗位姿，不需要强度值。
4. **查看深度和候选**：展开深度图。若返回可用候选，点击“预览候选 / 查看原位姿”，保持相同观察方向，比较多个不同深度处的静态建筑边缘，不只看一个局部。误差指标降低只表示内部一致性改善。
5. **人工核验**：满意后点“应用当前候选”；若更差或不确定，点“舍弃候选”。返回 rejected 时可以看深度及原因，但不能应用该候选。需要时进入“同名点精调”，完成投影核验。
6. **相邻帧复测**：切换到 `72.jpg` 再运行一次，检查候选跟随帧，未运行的帧没有被改写。随后可试多帧批处理、取消和逐帧检查，避免直接批量接受。
7. **跨场景与后续标注**：依次测试校园、图书馆、尖沙咀；确认位姿修正与标注按场景隔离。配准确认后，到“标注”在相邻全景圈选同一物体，执行多帧定位并核验点云候选。标注流程的用法见配准手册及轮廓编辑指南。

### 复测预期如何解释

此前五帧实测：六层 76 / 72 返回 candidate；校园 100、图书馆 4324、尖沙咀 001298 返回 rejected。该记录写入 `test-plan.json`，**是历史参考，不是保证每次相同的自动断言**。浏览器取样、JPEG 编码、设备数值与当前粗位姿均可能改变结果。

验收项目应分别记录：数据是否完整加载、深度是否生成、候选是否生成、投影人工核验是否改善、是否最终接受。不要把“生成候选”统计成“配准成功”。这四套数据没有独立外参真值，不能用来证明绝对角误差 ≤4°，也不适合当作模型训练的真值集。DA² 需要粗初值，这套包不会让它变成无初值全局配准。

## 5. 校验与重新制作

只需 Python 3.10+ 标准库，不需要模型或 GPU。完整解压后，在套件目录执行：

```text
python scripts/package_depth_test_suite.py --verify .
```

macOS 可用 `python3`；Windows 可用 `py -3`。校验包括每个文件字节数/SHA-256、PCD 点数和长度、2:1 全景尺寸、逐帧配对、旋转矩阵有效性及基础帧存在性。校验文件完整性不代表实际配准精度。

从源码目录重建（先运行 `npm run build` 与 `npm run package`）：

```text
python scripts/package_depth_test_suite.py --catalog "PATH_TO_PRIVATE_SCENE_CATALOG" --output "local-samples/depth-tests-NEW"
```

命令同时生成 Windows 和 macOS ZIP；目标目录和同名 ZIP 已存在时拒绝覆盖。输入为目录，其中包含 `scene-catalog.json`。默认复测计划对应本指南四套数据；换数据集需用 `--plan` 提供相同格式且逐帧匹配的测试计划。仅复制目录明确引用的必需数据，不递归收集旁边的日志、缓存、密钥或模型文件。

若只需生成配对数据目录而不打包应用，加 `--prepare-only`；可用已有应用运行：

```text
node scripts/serve.mjs --scene-dir "local-samples/depth-tests-NEW/scene-data" --port 44010
```

`local-samples/` 与 `release/` 已由 Git 忽略。含实际测绘数据的 ZIP 不上传公开仓库或 GitHub Actions；协作者通过获准的私有渠道共享数据。GitHub Actions 只用程序生成的微型格式夹具测试制作与校验流程，不需要这四套真实数据。
