本页保留历史版本背景。当前 0.14.1 的入口名称、导入限制与完整操作，以 [独立配准手册](REGISTRATION_MANUAL.md) 为准；[Windows/macOS PDF](manuals/README.md) 可离线阅读。

## 试用顺序

当前自动精配准使用无权重球面 NID 本机后端；部署、输入条件、质量检查与限制见 [自动配准说明](AUTOMATIC_REGISTRATION.md)。已有粗位姿仍是前提，候选须人工核验。
2. **同名点精调**：点“下一步：同名点”，自动进入同步分屏。在点云点静态建筑角点，再点全景同一位置。两侧显示相同编号；建议选 6–10 对，分散在不同方向与距离。至少四对才能求解。可撤销上一对或在更多设置中删除某一对。
3. **投影核验**：求解成功后进入叠加视图，核对建筑、路灯和固定设施边缘；误差过大时返回重选。保存并导出，再进入标注。拟合残差只说明这些点对的一致程度，不能替代独立精度验收。

顶部只有步骤、分屏/叠加、同步开关和更多设置。相机六个数值、原位姿恢复、自动配准服务配置和诊断信息折叠在“更多设置”。原有 3D 框、逐点分类、多帧目标定位和模型接口继续在“进入标注”后的工作台中使用；辅助模型栏默认折叠。

## 同步观察的含义

- 默认从**当前全景对应的相机位置**看点云，不再从场景外俯视。点云和全景共用世界空间的观测四元数与垂直视场角。
- 拖动任一视图，另一侧立即更新；滚轮同步改变视场角。两侧宽高比不同时，水平覆盖范围会不同，中心朝向和垂直视场保持一致。
- 切上一帧、下一帧或选择任意相邻帧时，点云相机移到新帧的位置，保持当前世界朝向及缩放；全景相机按该帧外参换算局部朝向，重新计算点云投影。
- 全景尚未解码、上传纹理时，两侧显示同步遮罩；快速连续切换会丢弃过期的图片回调。GPU 渲染循环持续运行，切帧耗时仍取决于磁盘、8K 图像解码及显卡，未承诺固定帧率。
- “投影叠加”为全宽球面全景叠加点云；切回分屏不丢失观测方向。“视角同步”关闭后可自由绕点云观察、平移或切俯视；重新开启回到当前采集位置与共享朝向。
- **观察与标定相互独立**：拖动、缩放不修改外参；只有导入、参数调整、同名点求解或接受算法候选才修改配准。参数改变会同时更新两侧换算。

## 新版真实场景

本机输出 `local-samples/trial-jsz-dense55m-001298/`，原始数据与旧试用样本均保留。

| 内容 | 0.11.0 试用场景 |
| --- | --- |
| 点云 | 4,500,000 个实际 RGB 点，PCD 约 72 MB |
| 范围 | 基准 INS 周围水平 55 m，相对世界高度 −8 至 +45 m |
| 抽样 | 2 cm 空间体素去重，约 652 万个占用体素中均匀保留 450 万代表点 |
| 源覆盖 | 筛选到约 5,574 万个源地图点；保留实际源点，不插值补面 |
| 全景 | 11 张原始 8192×4096 JPG；约 20.13 m 轨迹，约 2.667 s |
| 朝向初值 | INS 加本场景目视方向对照所得的 **180° 零方位粗假设** |

此前 75 万点在半径 45 m 内按原始点记录随机抽取，重复扫描容易占据抽样预算；半径太小也会截掉远处立面。新版扩大范围，先按空间体素去重，再保留更密的点，配合当前相机视点、固定像素点大小与高程/亮度增强，改善轮廓可辨性。高程与亮度增强只改变显示，原始 RGB 单独保留，彩色配准算法读取原始颜色。

180° 是这组场景的**可更改粗初值**，来自本次建筑、弧形立面和树冠方向对照，不是硬件标定结论，也不保证适用于其他数据。初始位姿中仍缺少经独立核验的杆臂、安装角及真值。原始 INS-only 位姿保存在 `registration-ins-only.json`，可在更多设置重新导入；待确认的六自由度 CSV 没有应用。当前未证明满足 4° 误差要求。

同名点应选择云和影像均存在的清晰静态角点。累积地图与图像的车辆、行人或植被细枝可能不同，不作为可靠对应。扩充点数不会生成原始扫描中不存在的几何；若该区域缺测，可换方向、相邻帧或更完整的地图。

## Windows 与 macOS

完整场景试用包均含同一平台构建和同一组实测资产：

| 系统 | 完整试用包 | 解压后启动 |
| --- | --- | --- |
| Windows | `SCRI-Scene-JSZ001298-Windows-v0.11.0.zip` | `Start-Scene-Windows.bat` |
| macOS | `SCRI-Scene-JSZ001298-macOS-v0.11.0.zip` | `Start-Scene-macOS.command`，或终端 `sh ./Start-Scene-macOS.command` |

安装 Node.js 20+，完整解压后启动，使用终端输出的 `?localScene=1` 地址。保持终端运行。服务只监听 localhost，自动避让占用端口。浏览器保存依赖主机与端口；更换来源前先导出。新点云重新抽样后生成新任务 ID，旧场景的逐点标签不会移植到新点索引。

源码目录启动：

```sh
npm run build
node scripts/serve.mjs --scene-dir local-samples/trial-jsz-dense55m-001298 --port 43952
```

macOS 可把 `--scene-dir` 改为复制后的场景目录。常规 GitHub Actions 平台包仍只含合成样本；含实测数据的 ZIP 保存在本机 `release/`，不自动上传 GitHub。

重新提取（两系统使用同一脚本；Mac 需用 `--vmms` / `--frames` 指向本机源文件）：

```sh
python scripts/prepare_trial_scene.py --radius 55 --max-points 4500000 --voxel-size 0.02 --panorama-yaw-offset 180 --output local-samples/new-dense-scene
```

`--panorama-yaw-offset` 默认 **0**。只有核验了相应数据的方向后才显式选用其他值；它在 INS 相机位姿右侧乘局部 Y 轴旋转，并额外保留 INS-only JSON。

```sh
npm run package
python scripts/package_scene_trial.py --scene local-samples/trial-jsz-dense55m-001298
```

## 同事开发入口与验收

| 文件 | 职责 |
| --- | --- |
| `src/viewSync.ts` | 世界观测方向/FOV 发布订阅、全景局部方向换算、编号标记 |
| `src/PointCloudView.tsx` | 同步模式固定光心环视；自由模式 OrbitControls；密点显示、原始 RGB 保留、真实点索引拾取 |
| `src/PanoramaView.tsx` | 接收共享朝向、反向发布拖动与缩放；切帧纹理生命周期；最多约 18 万点投影 |
| `src/RegistrationWorkflow.tsx` | 三步流程、帧导航、布局切换、折叠设置 |
| `src/App.tsx` | 逐帧配准状态、独立观测状态、载入遮罩与同名点求解衔接 |
| `scripts/prepare_trial_scene.py` | 分块空间去重、均匀体素代表点抽样、显式零方位假设 |

`ViewSync` 直接通知两台渲染相机，拖动不触发大型点云的 React 重新着色，也不反复回传形成循环。DOM 的 `data-view-quaternion`、`data-view-position` 和 `data-view-fov` 记录同步模式下实际使用的相机值，便于浏览器验收。

已执行：构建；配准矩阵/同名点/三角定位回归；同步数学与发布订阅测试；空间抽样保留孤立结构与坏 PCD 拒绝测试；真实浏览器双向拖动、同步缩放、相邻及快速切帧、两种布局、点对编号、保存刷新恢复。实测切到下一帧后，两侧相机位置同为约 `(-0.0149,-0.0117,-2.0351)`，世界四元数及 FOV 保持一致。验证用点对已清除，不作为标定成果。

测试命令为 `npm run test:view-sync`、`npm run test:registration`、`npm run test:local-scene` 和 `python scripts/test_trial_sampling.py`。Windows 完成真实数据图形界面实测；macOS 使用同源构建、脚本及 CI，实体 Mac 图形性能仍待同事验收。
