# 模型切换与审核工作流

## 当前可用功能

在“预标注接口”页按数据类型添加多个 HTTP 模型服务，填写名称与服务根地址。图片任务和点云／全景任务各自记住当前选择，标注页可随时切换。配置只保存在当前浏览器的 `localStorage`，键为 `atlas-model-profiles-v1` 和 `atlas-selected-models-v1`；旧的单地址配置会作为“原有 HTTP 服务”迁移。配置不包含密钥，也不会同步到其他电脑。

点击“运行当前图片”或“运行当前配对任务”后，浏览器才向所选服务上传**当前任务**文件。图片只上传一张；联合任务上传一份点云和一张全景。切换任务或模型会取消当前浏览器请求并丢弃未审核候选；服务端可能仍需自行清理已上传资产。不要把含真实数据的任务发给不受信任的服务。

预测进入紫色候选层，不覆盖已有框、逐点标签或配准。可逐项接受／忽略，也可批量处理。图片接受后立即进入本地复核状态，可撤销并导出 YOLO ZIP；有未处理候选时不能确认该图。联合任务接受对象后仍需点击“保存更改”或导出 JSON；逐点候选的接受操作只填充**尚未人工标注**的点，不替换已有点类别。已接受结果保留 `origin: "prediction"`、模型 ID／版本及可选置信度。

## 模型适配边界

| 数据 | 适配器 | 代码 | 输出 |
| --- | --- | --- | --- |
| 普通图片 | `atlas-image-v1` | `src/modelApi.ts` | 七类归一化 2D 框 |
| 点云 + 全景 | `atlas-paired-v0.2` | `src/prelabel.ts`、`src/modelApi.ts` | 3D 框、全景标记、可选逐点类别 |
| 普通图片／全景 | `qwen-vl-v1` | `src/modelApi.ts`、`scripts/llmGateway.mjs` | 图片 2D 框或全景 2D 区域候选 |
| 普通图片／全景 | `deepseek-vision-v1` | `src/modelApi.ts`、`scripts/llmGateway.mjs` | 图片 2D 框或全景 2D 区域候选 |

`src/modelRegistry.ts` 保存模型配置和数据类型选择；`src/ModelSettings.tsx` 管理服务；`src/ImageReview.tsx` 和 `src/PairModelBar.tsx` 负责运行与人工审核。**同协议的模型只需添加新的服务地址即可切换**。若模型输出格式不同，应在适配层新增转换函数，将外部结果校验并转成上表的标准格式，不应把模型专有字段散入标注组件。不能只更换地址就把任意格式的模型直接接入。

服务协议细节与 JSON 示例见 [预标注服务接口](MODEL_API.md)。服务端应处理 CORS、资产生命周期、权限、文件大小和异步推理；本地原型仅提供同步 HTTP 请求，上传超时 5 分钟、预测超时 2 分钟。当前没有真实模型、认证、批量作业、服务端数据库或多人并发控制。

千问与 DeepSeek 视觉的本机代理、双平台启动和数据传输边界见 [LLM 接入说明](LLM_PROVIDERS.md)。它按提供方分别使用环境变量中的 Key 和受控上游地址；UI 可以保存与切换多个已获准的模型名称。全景模式只输出 2D 候选，3D 框仍需专门的点云模型或人工标注。

## 本地模拟服务

开发者可运行 `node examples/mock-model-server.mjs`（仅监听 `127.0.0.1:43251`，不保存文件），随后添加以下测试配置：

- 图片模型 A：`http://127.0.0.1:43251/image-a`
- 图片模型 B：`http://127.0.0.1:43251/image-b`
- 点云／全景模型：`http://127.0.0.1:43251/paired`

两种图片模型返回不同类别的单个候选框，适合验证切换与人工审核。模拟服务不做真正推理，测试完可在配置页删除。
